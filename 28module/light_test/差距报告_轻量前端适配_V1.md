### 1.1 为什么旧注入直接失效（不是参数问题）

`html_model/联机注入.js:130-133`：

```js
if (!project || !Array.isArray(project.axes) ||
    project.axes.length !== FRAME_AXIS_IDS.length || ...) {
  return setTimeout(boot, 100);   // 静默无限重试
}
```

细化工程 19 轴 ≠ 帧 21 槽 → **永远不 boot、永远不连、也不报错**。这是"页面能开但没反应"的机制来源，必须换一套注入（`light_test/联机注入_light.js`）。

### 1.2 细化前端的隐藏机制：弹簧回位

细化查看器带「接触传动 · 可推动对象 · 移动轴时自动推动/回位」。实测：

- `__TD_VIZ__.setAxis(ax, v, true)` → 当帧生效，**下一帧被弹回原值**，`ax.current` 归零；
- `setAxis(ax, v, false)` → 同样被弹回；
- **只有走滑块 `input.value` + `input.oninput` 才稳定**（与用户拖动同一条路径）。

所以注入脚本的应用链是「滑块优先，`setAxis` 仅作兜底」。这一条不试出来，轴会"动一下就弹回去"，很容易被误判成联机没通。

### 2.1 唯一需要动模型的缺陷：`axis_ISS_FA_X`

- 模型声明 `0 = CAD 取片位，+1050 = 交接位`，量程 `0~1235`；
- 实测 `FA_X=+1050` → 翻转吸盘 X 从 1199.85 走到 **2249.85**（+X，**远离**键合头）；
- 键合头在 X = **−42.50**，要交接必须走到 **−1242.35**（= 1199.85 − (−42.50)）；
- 结论：**正方向接反，且量程 1235 < 需要的 1242.35，差 7.35 mm**。

处置：不改用户源文件，`tools/build_light_online.py` 在**生成的联机产物**里把 `axis_ISS_FA_X.min` 打成 −1243（`[build] 模型量程补丁` 有打印）。源文件 sha256 每次构建前后校验不变（`ceeb4f62d16c…`）。**建议后续在 TwinDOM 工程里把该轴方向/量程正式修正**，否则每次导出都要重新打补丁。

## 5. 碰撞盒缺口（已实测复现，副本默认关闭）

现成 `sandboxes.json` = 146 盒 / 895 对，由**旧** `d2w_front.json` 生成。拿它跑细化模型的姿态，直接 409：

```
FA_X → -1242.35   ✗ 409 沙盒干涉：对准相机承载台 × 翻转模块Rx支架 / Rz承载台…（共 7 对）

WS_LS_X → -40.02  ✓ 200（这条本来就在旧模型的轨迹上）
```

**这不是误判，是盒子坐标确实来自另一台模型。** 于是副本里 `main.py` 改成默认关闭（`D2W_COLLISION=1` 才打开），并在启动日志明确打印，避免用户以为"模型坏了"。

### 重建方案（未做，建议下一轮）

现成 `tools/gen_sandboxes.py` 只认原生几何（Box/Cylinder 参数），细化模型 871 件是 GLB 网格，它算不出 AABB。可行路径：

1. 用已经跑通的钩子批量导出「对象 id → 世界 AABB + 归属轴（沿父链找最近的 axis.movingObjectId）」——一次 CDP 评估就能出 972 条；
2. 给 `gen_sandboxes.py` 加一个 `--aabb-json` 输入通道，跳过几何解析，直接吃步骤 1 的 AABB；
3. 只保留**运动模块**（AS / WS / BS / ISS / 蓝膜台）之间的对，避免 972 件全量把 1 kHz 物理线程拖垮；
4. 用三姿态 + 一条完整 flow 回归验证不再误拦、也不漏拦。
