# 联机版手动验证步骤

## 产物

- `html_model/d2w_online.html` — 原查看器逐字节复制 + `</body>` 前**内联**整块 `<script>联机注入.js 全文</script>`（自 2026-08-17 起不再用 `<script src>` 引用，见下方"已知问题排查记录"）
- `html_model/联机注入.js` — 联机逻辑源文件（WS 客户端 + HUD + 滑块联动）；**改动它之后必须重新构建**：
  ```bash
  python backend/tools/build_online_html.py
  ```
  构建脚本断言：原 html 构建前后 SHA256 不变、产物 = 原文件逐字节前缀 + 内联脚本块
- `backend/tests/stub_server.py` — 协议桩服务器（纯标准库，500Hz 正弦数据）

## 步骤

### 1. 启动桩服务器

```bash
cd backend/tests
python -u stub_server.py
```

应打印：`[stub] 桩服务器监听 ws://127.0.0.1:9010/ws ，500Hz 推送 21 轴（Ctrl+C 退出）`

### 2. 打开联机版页面

浏览器（Chrome/Edge）直接打开 `html_model/d2w_online.html`（file:// 即可，WS 不受同源限制）。

### 3. 联机状态验证（HUD，右上角半透明悬浮层）

连接成功后 HUD 应显示：

- `联机状态  ● 已连接`（边框变绿）
- `推送频率  ~500 Hz`（实测 490~510 之间波动为正常）
- `单向延迟  x.xx ms (p50)`——本机同时钟，应 **< 1ms**，这是"1ms 级延迟"的直接证据
- `丢帧计数  0`（本机回环应为 0；持续增长说明推送或解码有问题）
- `渲染 fps  ~60`
- `滑块模式  联机（拖动→后端 move）`
- `脚本错误  无`（若非"无"，该行为真实错误 message + 位置，直接据此定位；内联后不再是 "Script error."）

同时 3D 场景中各运动轴应做平滑正弦往复运动（滑块数值也在实时跳动）。

**单位约定（协议 V1 起）**：线上帧旋转轴为 rad、模型内部为 deg，换算在注入脚本边界完成。桩服务器旋转轴幅值：WS_Rz ≈±0.014rad（滑块显示 ±0.8° 左右摆动）、BS_CAL_Rx/Ry 与 AS_Rx/Ry ≈±0.0014rad（滑块显示 ±0.08° 微动）、FA_Rx ≈±1.57rad（±90°）、CH_Rz ≈±2.09rad（±120°）；直线轴为 mm。旋转轴滑块上看到的数值应为 deg 量级（如 CH_Rz 在 -120~+120 间摆动），而不是 ±2 的小数——若显示 ±2 说明 rad→deg 换算缺失。

### 4. 滑块联动验证（前端 → 后端指令）

联机状态下拖动左下角任意轴滑块，桩服务器终端应打印：

```
[stub] 收到指令: {"cmd": "move", "axis": "axis_xxx", "target": 12.3}
```

- 直线轴 target 为 mm；**旋转轴 target 为 rad**——例如把 CH_Rz 滑块拖到 120°，打印的 target 应 ≈2.094（rad），而不是 120
- 拖动过程中约 30Hz 节流发送，松手后拖尾补发最终值
- 正在拖动的轴不会被数据流覆盖（松手后恢复跟随流值）

### 5. 断线/重连验证

1. Ctrl+C 停掉桩服务器 → HUD 1 秒内变为 `○ 未连接（1s 重连中）`（边框变红），滑块模式变回 `单机（本地驱动）`，此时拖滑块为纯本地行为（不依赖后端）
2. 重新启动桩服务器 → 1 秒内自动重连，HUD 恢复绿色，运动恢复

### 6. 对照实验（可选）

打开原版 `d2w_front.html`：无 HUD、无运动、滑块纯本地——确认注入未污染原文件。

- 108 字节帧偏移（magic/version/count/sim_time/wall_time/seq/values）与协议逐项 roundtrip
- 桩服务器：WS 握手、503Hz 实测推送、seq 无跳号、客户端 move/estop 指令正确解析打印、客户端断开后推送线程干净退出

- test_client.py 回归 18/18（2026-08-17 修复后复跑）

## 已知问题排查记录（2026-08-17）

**现象 1：页面中央红色弹窗 "三维模型启动失败: Script error."（3D 背景和滑块面板正常）**

根因（已用 Edge headless 复现并验证修复）：
1. 直接原因：联机注入.js 的 `boot()` 调用了**从未定义的 `initSliderHook()`**，`ReferenceError` 在 `initHud()` 之后、`connect()` 与 `requestAnimationFrame(renderLoop)` 之前抛出——这同时解释了现象 2（HUD 显示但永远"未连接"、fps 0）。修复后还暴露出一个同型潜伏 bug：`axesById` 原为 `boot` 局部变量，渲染循环引用它会 `ReferenceError`，已提升为 IIFE 作用域。
2. 为什么只看到 "Script error."：file:// 页面用 `<script src>` 引用的外部脚本属跨域（opaque origin），浏览器按规范把其中异常洗成无详情的 "Script error."，触发 TwinDOM 查看器的 window.onerror 红色弹窗。
3. 修复：注入脚本改为**内联嵌入**联机版 html（同源，报错有真实 message + 行号）；boot / WS 回调 / renderLoop 全部 try/catch，异常只写 console 和 HUD "脚本错误"行，不再冒泡；另有 window 'error' 监听兜底记录真实错误。

**现象 2：HUD "未连接（1s 重连中）" 且 "渲染 fps 0"（后端实际在跑）**

根因：与现象 1 同源——`initSliderHook` ReferenceError 使 `connect()` 和渲染循环从未启动，并非 WS 握手被后端拒绝。证据：tests/test_browser_handshake.py 用逐字模拟的浏览器握手头（含 `Origin: null`、`permessage-deflate`）连真实后端，101 通过、497Hz 收帧、ping/pong 正常；Edge headless 实测修复后页面 `已连接 506Hz+ 丢帧 0`。

**回归确认步骤（每次改动联机注入.js 后）**：

```bash
python backend/tools/build_online_html.py        # 1. 重建内联版
python backend/tests/test_client.py              # 2. 后端回归（自启 runtime），应 18/18
python backend/runtime/main.py &                 # 3. 保持后端运行
python backend/tests/test_browser_handshake.py   # 4. 浏览器握手头兼容，应 3 项 PASS
python backend/tests/edge_headless_check.py      # 5. 真实 Edge 验证，应 PASS
```

edge_headless_check.py 判定项：HUD 存在、`已连接`、推送频率 450~560Hz（headless 事件循环拥塞导致成批处理，窗口计数有尖峰，权威频率以 test_browser_handshake.py 为准）、fps>0、`脚本错误  无`、无"三维模型启动失败"弹窗。

## 离线运行验收（硬性要求：完全无互联网可用）

**静态检查**（2026-08-17 实测）——联机版.html 全量扫描外部引用：

```bash
grep -o 'https\?://[^"'\'' )\`\\<>]*' html_model/d2w_online.html | grep -v '127\.0\.0\.1\|localhost' | sort | uniq -c
```

结果仅 2 处，均为**非加载性字符串**：

| 引用 | 实际身份 |
|---|---|
| `https://jcgt.org/published/0007/04/01/` | three.js GLSL 着色器**注释**里的论文出处（GGX 重要性采样） |
| `http://www.w3.org/1999/xhtml` | `document.createElementNS()` 的 XML **命名空间常量**，浏览器从不请求它 |

其他加载向量全部为零：`<script src>` 0、`<link>` 0、`@import` 0、`url()` 0、协议相对 `src="//"` 0、动态 `import()` 0、XHR/EventSource/sendBeacon 0。仅有的 4 处 `fetch(` 都在 three.js FileLoader 与查看器自带 glTF 加载器内，目标是运行时从**内嵌模型数据**生成的 blob:/data: URL。唯一网络出口是 `ws://127.0.0.1:9010/ws`（本机回环）。联机注入.js 无任何 http/https 引用。

**断网手动验收步骤**：

1. 禁用全部网卡/拔网线（或飞行模式）
2. `python backend/runtime/main.py` —— 应正常启动（纯标准库，仅绑定 127.0.0.1）
3. 浏览器打开联机版 html —— 模型正常渲染、HUD `已连接`、推送频率 ~500Hz、各轴随数据流运动、拖滑块后端能收到 move 指令
4. 任一步异常即不满足离线要求；预期全绿，因为上述静态检查已证明无任何外部依赖

### A. 面板 IO 监视页（panel/index.html，"IO 监视" tab）

## 已知限制

- 单向延迟基于本机同时钟（前后端同机有效）；跨机部署时该值不含时钟偏差校正。另：Edge headless（SwiftShader 软渲染，fps~11）下事件循环拥塞会使该值虚高到 ~130ms，属测试环境伪影，非链路真实延迟
- 若查看器自身（非注入脚本）在 window.onerror 抛出异常，HUD "脚本错误"行会显示 `window: ...`，注意甄别来源
