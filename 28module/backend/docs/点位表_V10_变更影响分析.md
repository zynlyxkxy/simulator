# 点位表 V6→V10 变更影响分析（2026-10-14，迭代 69）

> 事实源：`1928运动固件点位表_V10/1928运动固件点位表_V10.xlsx`（下位机同事 2026-10 更新），
> dump `1928运动固件点位表_V10/点位表_dump.txt`（与 V6 同款格式，生成器见本文件 §5）。
> 对比基准：`1928运动固件点位表_V6/点位表_dump.txt`（V6 保留作历史）。
> 方法：双 dump 的 Cordis token 集合格 diff（净 −72/+56）+ 五 sheet 行级/格级 diff + 全模型消费面 grep 定位。

## 1. 五 sheet 变化总览

| sheet | 行数 | 变化性质 |
|---|---|---|
| PLC_IO_点表名称定义 | 136→136 | 格式（GVL_IO 前缀上移到列头、F/S 列补填叶名）+ 少量实质改名/搬家 |

## 2. 实质变化明细

### 2.1 GVL_IO 列格式变化（非删除）
列头改"PLC侧变量名定义(GVL_IO.)"、格内只写叶名（如 `iSystemOn`）；且 V6 空着的
键合分系统（F 列）/芯片传输分系统（S 列）/气控箱（F 列）三处 PLC 变量名列**补齐**了叶名
（如 `iArm_Z_HandOffSignal`、`WT_WaferVac`）。GVL_IO 点一个没少，信息量反而增加
（生成器口径下 GVL_IO.* 点 51→153 个）。

### 2.2 芯片真空阀搬家（SS_Bonding.M_BS → SS_CH.M_FA）
- `M_BS.{o}ChipVacValveNear/Remote` → `M_CH.M_FA.{o}ChipVacValveNear/Remote`（归属从键合臂改为翻转模块）
- `M_CH.M_FA.ChipVacValue` → `M_CH.M_FA.iChipVacValue`（observe 加 i 前缀）

### 2.3 气路观测改名（10 个，气控箱）
| V6 | V10 |
|---|---|
| `M_AIR.ChipTransferPos.PressureSwitch.oValue` | `M_AIR.ChipTransferPos.oValue` |
| `M_AIR.ChipTransferNeg.PressureSwitch.oValue` | `M_AIR.ChipTransferNeg.oValue` |
| `M_AIR.ChipVacOpen.PressureSwitch.oValue` | `M_AIR.ChipVac.PressureSwitch.oValue` |
| `M_AIR.AS_CameraCooling_1..4.oValue` | `M_AIR.AS_CameraCooling_Flow1..4.oValue` |
| `M_AIR.FA_Exhaust.oValue` | `M_AIR.FA_ExhaustFlow.oValue` |
| `M_AIR.ExhaustReserve_1/2.oValue` | `M_AIR.ExhaustReserve_Flow1/2.oValue` |

注：ChipVacOpen→ChipVac 顺带修正了 V6 与引擎气路回路名（`ChipVac`）的不一致——
V6 观测点挂在 `ChipVacOpen` 下而引擎合成写出在 `ChipVac` 下，V10 后两者对齐。

### 2.4 粗对准相机命令名修正
command `M_AS.oAS_CameraOn`（V6 笔误，与 observe 同名）→ `M_AS.AS_CameraOn`；
observe `oAS_CameraOn` 不变。**效果**：V10 后命令路径叶名命中 `CAMERA_TRIGGERS`
（plc_http.py），PLC 硬触发粗对准相机自此走通触发链（V6 口径下该命令点只能落通用写入）。

### 2.5 键合臂位置传感器标定
- observe：`M_WS.oAramPosSensorCalibrate_1`（V6 笔误 Aram、两行同点）→
  `M_BS.oArmPosSensorCalibrate_1` / `M_BS.oArmPosSensorCalibrate_2`（修正拼写+搬到键合臂+分两通道）
- command：`M_WS.AramPosSensorCalibrate_1` 保留 + 新增 `M_WS.AramPosSensorCalibrate_2`（H55/H56 不再同点）

### 2.6 新增 observe
`M_BS.iArm_Z_PitchFpos_2`（_1 保留，键合臂 Z 向Pitch 方向位置反馈第二通道）。

### 2.7 M_ES 蓝膜台接口大改版（蓝膜台翻转及加压 sheet 18→40 行）
**删除**：命令 `ES_GvieBackDie`（一键退片）/`ES_MoveToNextChip`（移动至下一芯片）；
观测 `oX_CurrentPos`/`oY_CurrentPos`/`oRz_CurentPos`（轴位置外发取消）。

**新增命令**（8）：`ES_Initialize`、`ES_Photo(Bool Allow)`（无遮挡时给相机快门信号）、
`ES_HeatAirGun(Bool Open)`、`ES_ChangePunch(Int16 PunchNum, Bool oChange)`、
`ES_PickNozzle(Int16)`/`ES_PlaceNozzle(Int16)`、`ES_SetThetaAngle(Real Angle)`、
`ES_ExpandingHeight`。

**新增命令回执**（12）：oStart/oStop/oReset/oEmergencyStop/oInitState/oPhoto_Available/
oHeatAirGunOpen/oPunchNum/oPickNozzleNum/oPlaceNozzleNum/oThetaAngle/oExpandHeight。

**新增状态输入**（13）：iES_Initializing/InitializeFinish/AutoRun/AlarmOn/WarningOn/
PhontoNeeded/PhotoFinished/PickChipAllowed/InChangePunch/CurThetaAngle/CurExpandHeight/
CurPunchNum/CurPickNozzleNum/CurPlaceNozzleNum/InPickNozzle/InPlaceNozzle。

**不变**：翻转 buffer 接口（`M_ACS_Buffer.SetBufferNumber/StopBuffer/RunBuffer/ResumeBuffer`
+ oBufferDo/oBufferNum，注释"蓝膜台外包，只有这几个接口，翻转交接芯片逻辑流程写在 buffer 里"）
与加压接口（`M_BS.BondingByForceManual`/`oActualForce`，"沿用 1920 模块"）。

## 3. 对模型的影响分析

### 无影响（模型工作方式不变）
- **21 轴**：轴名/Cordis 名/ACS 轴号/回零方式/行程全部未变 → axes_config.py、ACS 模拟器、
  回零 buffer、误差链、视觉、测校、工艺流全部不动
- **温控**点位零变化；**翻转 buffer / 键合力**命令面不变
- ACS SDK 指令面 / Cordis MCS HTTP 五服务 / MQTT 线协议 / RPC 层均不涉及

### 有影响（全部集中在 IO 点命名空间层）
| 消费方 | 影响 | 处理 |
|---|---|---|
| `runtime/io_points.json`（生成物） | IO 命名空间更新：328→465 点（删 21/增 158，GVL_IO 51→153） | 已重新生成 |
| `runtime/gen_io_points.py` | V10 GVL_IO 叶名无前缀，旧正则抓不到 | 已适配（按 sheet 追踪 "(GVL_IO.)" 列补前缀）+ COMMAND_LEAVES/REAL_HINTS 更新 |
| `runtime/engine.py` | ES 命令集变化；M_ES.oX/oY 观测被删；aram 校准 observe 改名搬家 | es_command 重写（新命令集+回执/状态置位）；oX/oY 写出删除；aram_calibrate 写 M_BS.oArmPosSensorCalibrate_1/2 |
| `runtime/plc_http.py` | ES_CMDS 名单、aram 注释 | 已跟进（删 2 加 8；_1/_2 独立通道） |
| `panel/index.html` | AIR_CN 中文映射 7 键改名（失配只回退英文原名，不崩） | 已跟进（_Flow 系；ChipVacOpen 行删除） |
| PLC HTTP 接口面 | 旧路径失联、新路径上线（/io/observe、/io/command 按路径寻址） | 即本迭代目的——对齐真机 V10 |
| 面板 fixture `tests/panel_io_dom.html`/`panel_mock.py` | 手动检查工具，不在回归套件内 | 本轮不更新（遗留） |
| 对外桥接/整机软件 | 若按 V6 旧路径消费被删/改名点会断 | 真机即 V10，应跟上；M_ES 被删两命令模型侧本就无仿真行为、流程编排零消费（已核实） |

## 4. 结论

**可以更新且已更新**（迭代 69）。变化全部在 IO 点面，语义清晰；模型侧物理/运动/视觉/测校/工艺
行为零变化。ES 新命令的仿真语义维持"蓝膜台外包黑盒"口径：接受命令+回执置位+有来源的状态回读，
不做真实流程仿真（换顶针/吸嘴/扩膜等物理行为待真机联调有需求再立项）。
