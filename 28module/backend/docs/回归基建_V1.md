## 1. 测试套件怎么跑（test_client.py）

一律用项目内置解释器（环境变量按需）：

```bat
set PYTHONNOUSERSITE=1
set PYTHONIOENCODING=utf-8
set PYTHONUTF8=1
env\python\python.exe backend\tests\test_client.py [参数]
```

| 跑法 | 命令 | 说明 |
| --- | --- | --- |
| quick（默认） | `test_client.py` | 日常回归；段表 `test_client.py:11595-11676` 里 `套件="both"` 的段，full-only 段与 fblock() 门控用例跳过（末尾打印跳过清单） |
| full | `test_client.py --full` | 全量，交付/接口变更前必跑 |
| 定向 `-k` | `test_client.py -k "i37 or nonortho"` | tokens 子串匹配 check 名，只跑 `_KW_SEG_MAP` 映射段（`test_client.py:11271-11276`）；`{i36,i37,nonortho}` 子集另把扫描轴误差地图归零（finally 按字节恢复） |
| 定向 `--segs` | `test_client.py --segs 1.stream,3.plc` | 只跑列出的段（段名见段表） |
| 结果外置 | `--out PATH` | exit 前 dump `{suite, shard_id, results, skipped, seg_times, wall_s}` JSON |
| 裸引擎 | `--bare --shard-id N --segs ...` | 进程内 BareHarness（不起真后端），编排器专用，见 §5 |

套件自拉起真后端（`runtime/main.py`），需要 9010 空闲；启动前自检 9010 被占
会直接报错退 1（`test_client.py:11350-11357`）。跑完自动关后端。

## 2. run_regression.py —— 定时/日常回归 runner

`backend/tests/run_regression.py`，用法：

```bat
env\python\python.exe backend\tests\run_regression.py [任意 test_client 参数...]
```

空参 = quick；`--full` / `--segs a,b` / `-k "..."` 等原样透传（`--out` 例外：
runner 统一管理产物路径，透传的 `--out` 被剥掉并提示）。流程：

1. 预检 9010：TCP 能连上即视为被占 → 中文报错退 1；
2. 自动补 `--out Temp/regression_logs/<suite>_yyyymmdd_HHMMSS.json`，subprocess
   跑 test_client，stdout 直落同名 `.log`（文件句柄，不走管道），退出码原样继承；
3. 跑完写 `Temp/regression_logs/latest.json`：
   `{ts, suite, passed, total, wall_s, exit_code, fails:[{name,detail}], log, json}`
   （passed/total/fails 解析自 `--out` JSON；套件中途崩溃时记 null，exit_code 照实）；
4. 日志轮转：`Temp/regression_logs/` 只留最近 30 份（文件名时间戳字典序=时序，
   log/json 成对删；`latest.json` 不参与轮转）。

## 3. daily_regression.bat + Windows 计划任务

根目录 `daily_regression.bat`（**GBK 编码 + CRLF 行尾**，cmd 按系统 ANSI 解析；
改动后必须保持该编码，参考 start.bat）：chcp 936 → 校验 `env\python\python.exe`
存在（缺失中文报错退 1）→ `set PYTHONNOUSERSITE=1` → 调 run_regression.py 透传
`%*` → `exit /b %errorlevel%`。可手动跑：`daily_regression.bat --segs 1.stream`。

计划任务三命令（注册/查询/移除；Git Bash 下需 `MSYS_NO_PATHCONV=1` 前缀防
`/create` 被转成路径）：

```bat
schtasks /create /tn "D2W_DailyRegression" /tr "\"C:\Users\e-hao.wu\Desktop\28模型开发\daily_regression.bat\"" /sc daily /st 09:17 /f
schtasks /query /tn "D2W_DailyRegression" /v /fo list
schtasks /delete /tn "D2W_DailyRegression" /f
```

迭代 50 已注册：每天 09:17 跑 quick（登录交互态才触发——schtasks 默认，未加
`/ru`；无人值守值守场景请自行补 `/ru <用户> /rp <密码>` 或改"不管用户是否
登录都运行"）。产物看 `Temp/regression_logs/latest.json` 与同名 log/json。

## 5. run_full_parallel.py —— 并行分片编排器（迭代 50 复活）

迭代 19 埋了 `--bare/--segs/--out/--shard-id` 分片参数与
`backend/tests/bare_harness.py` 裸引擎 harness（机制见其头部 docstring），
但编排器本体一直缺失（`test_client.py:137`、`:11244`、`:11516` 三处注释引用
`tools/run_full_parallel.py`）——迭代 50 补齐。

### 5.1 用法

```bat
env\python\python.exe backend\tools\run_full_parallel.py                 :: quick 拆 3 片（默认）
env\python\python.exe backend\tools\run_full_parallel.py --shards 4      :: 4 片
env\python\python.exe backend\tools\run_full_parallel.py --segs 3.plc,15.recipe
env\python\python.exe backend\tools\run_full_parallel.py --concurrent    :: bare 相与全栈片也并发
env\python\python.exe backend\tools\run_full_parallel.py --full          :: 全量口径（未实测路径）
```

默认**分相执行**：先 bare 各片并发（无端口、per-shard tempdir + MQTT 派生
11883+shard-id 隔离），跑完再起全栈片（真后端 9010）——防裸引擎全速 tick
线程抢 CPU 污染全栈片 1000Hz/500Hz 墙钟红线。`--concurrent` 全部一起跑
（20 核机子集实测：1.stream 500Hz 红线段与 bare 19.12.iter8 全并发仍 5/5
过；全量 --concurrent 未实测，机器余量足时可自行尝试）。

每片 `--out Temp/_par_shard<i>.json`、stdout 落 `Temp/_par_shard<i>.log`；
聚合打印各片通过数/墙钟、FAIL 明细（带片号）、总墙钟 vs 串行参考；任一 FAIL
或片进程非零退出 → 退 1。

### 5.3 bare vs 全栈一致性实测（迭代 50）

方法：16 个 bare 段按编排器默认分片（片A=3.plc/14.collision/15.recipe，
片B=13 个 19.x 段）各跑一遍，与同段集全栈串行跑逐 check 名比对
（`--out` JSON 的 results 名字→结果映射）。

- 代表段单跑：3.plc bare 4/4 == 串行；19.12.iter8 bare 18/18 == 串行；
  19.29.nonortho bare 全挂（"9200 帧处理超时"）→ 裁定全栈；1.stream 为
  WS 段，bare 防御跳过（本质上不能 bare，编排器自动归全栈片）；
- 修复后全量比对：bare 两聚合 109 用例 vs 串行同段集 109 用例，名字集合
  完全一致、逐用例结果完全一致（修复过程见 §5.2：recipe.persist 直读落盘
  路径、i21.* 材质服务 503、19.24.iter20 直 urllib 打 9010 三处挖出）；
- 19.25.iter21 依赖段序自愈（iter15 finally restore_default），单段抽跑
  需 repo recipe.json 干净——见 §6。

### 5.4 实测数据（20 核机，2026-09-21）

- 串行 quick：**395/395 通过，墙钟 646.7s**；19.29.nonortho 一段 442.4s
  （占 68%，9200 帧通道本质上不能 bare，是全栈片的不可压缩长杆）；
- 并行 3 片（默认分相）：片0(bare 3 段) 8.9s、片1(bare 13 段) 56.6s、
  片2(全栈 24 段) 608.1s，**聚合 395/395 与串行逐名一致，总墙钟 664.8s**
  （≈串行 1.03×——bare 相只省 ~1min，被全栈片 nonortho 长杆淹没）；
- bare 单段墙钟 vs 全栈同段：iter8 92.4s vs 38.7s、wafer_ega 14.5s vs
  6.3s——裸引擎 tick 线程与测试线程同进程抢 GIL，墙钟驱动段反而慢
  ~2×（且对外部负载敏感：三路并发时 iter8 bare 涨到 141s）；纯 API 段
  bare 快 5-10×（3.plc 0.8s vs 0.7s+后端拉起 ~15s）；
- 结论：quick 口径并行收益≈0（长杆不可迁移），编排器价值在 ① 断链复活
  的隔离分片方法论、② `--segs` 显式模式的多片定向回归（如 19.x 家族
  56s 单出结果）、③ 为后续 full 套件/新可迁移重段留好分片框架。

## 6. 排障指引

- **9010 被占**（test_client / run_regression / run_full_parallel 全栈片都会
  预检报错）：
  ```bat
  netstat -ano | findstr :9010 | findstr LISTENING
  :: 拿到 PID 后验明是本工作区 python 再杀（Git Bash 下 taskkill 用 //F）：
  wmic process where "ProcessId=<pid>" get CommandLine
  taskkill /PID <pid> /F
  ```
  其他端口同理：9101(ACS) 9102(PLC) 9190(MCS) 1883(MQTT) 9200(视觉 TCP)。
  套件正常退出会自动关后端；异常 Ctrl-C/崩溃可能留孤儿子进程。
- **跑套件时别用浏览器开着面板/联机页**（2026-09-21 迭代 54 实测事故）：
  start.bat 会打开 `/panel` 和 3D 联机页标签——面板"视觉软件"tab 的 live
  预览以 ~4.5Hz 拉 REAL 9MP 渲染，若标签还指向 9010，套件自起的后端会被
  浏览器打满 GIL：tick 掉到 ~880Hz、建模板示教 >13s 超过测试 5s 超时，
  套件崩在 `vision 模板 CRUD` 这类重调用上。跑套件前关掉这些标签；
  建模板调用已统一 `http_post_tpl`（60s 超时，test_metrology 同款先例），
  但浏览器负载仍会污染 perf 红线窗。
- **回归日志去哪看**：定时/手动 run_regression → `Temp/regression_logs/`
  （`latest.json` 看最近一次汇总，`<suite>_<时间戳>.log` 看套件全文，
  `.json` 看逐用例机器可读结果）；并行分片 → `Temp/_par_shard<i>.log/.json`。
- **bare 片崩溃**：片 JSON 缺失时编排器标"崩溃片"，栈在对应
  `Temp/_par_shard<i>.log` 末尾；单片可单独复现：
  `test_client.py --bare --shard-id <i> --segs <片内段> --out Temp/_dbg.json`。
- **-k 定向段改了误差地图没恢复**：`-k {i36,i37,nonortho}` 会在 backend 启动
  前归零 `runtime/error_maps/*_simulated.csv` 并注入 low_order.json
  scale_ppm，finally 按字节恢复；进程被强杀会留脏文件，`git status`
  检查 `backend/runtime/error_maps/` 即可发现。
- **i21.recipe_fast_noise_default FAIL（readback up/down=0.15）**：19.25.iter21
  的默认值断言依赖段首 recipe 为出厂默认（{coarse:0.15, up:0.1, down:0.1}），
  而该段自己的 PUT 用例收尾把 fast_noise_px 留成全 0.15——完整套件靠
  19.21.iter15 段尾 finally 的 restore_default（`test_client.py:8803`）自愈
  （bare 片同含 iter15→iter21 顺序，同样自愈）；`--segs` 子集不含
  19.21.iter15 的部分跑会在 repo recipe.json 留脏，下一次部分跑该断言挂。
  处置：完整跑一遍套件自愈，或对已启动后端手动
  `POST /api/recipe/restore_default`。
