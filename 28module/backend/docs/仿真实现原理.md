# ACS / PLC 仿真实现原理 —— 与真机的对照和可迁移性

> 回答三个问题：现在的仿真内部是怎么做的？和真机一样吗？调试好之后代码能不能直接用到真实设备上？

## 1. 仿真内部是怎么实现的

### ACS 模拟器（`runtime/acs_tcp.py` + `engine.py`）

- **对外**：TCP 服务（9101），换行分隔 JSON 指令：enable / home / move / stop / estop / getpos / buffer 系列（SetBufferNumber / RunBuffer / StopBuffer / ResumeBuffer，观测 oBufferDo / oBufferNum）。
- **对内**：10 根 ACS 轴共享 1kHz 物理线程。每条 move 指令经 S 曲线规划器（jerk 限幅，`trajectory.py`）生成时间参数化轨迹，逐 tick 积分位置；软限位钳位、到位判定、运动中标志。
- **回零**：CiA402 方法 17/18 语义的状态机（快速逼近限位开关 → 慢速退出 → 慢速锁定边沿 → 写 home_offset → homed），限位开关是仿真的（软限位外扩 2% 处的虚拟开关）。
- **buffer**：预置的轴运动序列程序（如翻转交接），模拟真机"固化在控制器里、由上位触发"的动作段。

### PLC 模拟器（`runtime/plc_http.py` + `points.py`）

- **对外**：HTTP 服务（9102）：`/io/command`（按 Cordis 变量路径下命令）、`/io/observe`、`/io/snapshot`。
- **对内**：471 个点位状态表（`io_points.json`，从 V10 点位表提取并加入模型扩展点），加分类型物理模型：
  - 气路：Command（OpenPositive/OpenNegtive/OpenAir）→ 状态观测与压强/流量按一阶惯性（τ≈0.2s）过渡；
  - 温控：脉冲加热 200℃/s、硅片台加热慢速升温的一阶模型（SetTargetTempWithPlan 等命令）；
  - 键合力：弹簧接触真值 → 传感误差/标定 → oActualForce；BondingByForceManual 另走力 PID；
  - 独立搜力（迭代 78）：ForceSearch 触发引擎内 1kHz 状态机，从当前 BS_Arm_Z 下行，
    到力停轴、50ms 平均力稳定确认后锁存 oForceSearchDone；不启动力 PID、不转移动料；
  - PLC 管辖的 11 根轴（Epin×3、键合臂 Z、校准台 Rx/Ry、翻转 Z/Rx/Rz、蓝膜台 X/Y）走与 ACS 相同的轨迹引擎。

### 误差系统（`error_system.py`）

读取时注入：actual = 伺服实际位置 + 重复定位（到位重采样）+ scale_ppm 比例误差 + error map 分段线性插值。轨迹积分永远走名义值。

迭代 77 起顶栏「误差全关」（`POST /api/error_injection {"disabled":true}`）统一屏蔽全部仿真误差，包括轴控 `3σ repeat`、6DOF、模态/热/翘曲、视觉/共焦/温力、上片和工艺误差；独立开关和参数保留，恢复后继续，轨迹/温控/联锁不关闭。

### 伺服环动态（`engine.py` + `axes_config.py`，2026-08-19 引入）

把"规划到位"和"实际静止"分离，模拟真机位置环的跟随误差与到位整定：

- **模型**：每轴维护伺服实际位置 `x_actual`，每 tick 一阶滞后跟随名义值 `pos`：
  `x_actual += (pos - x_actual) × TICK_DT / tau`；跟随误差 `pe = pos - x_actual`。
- **状态机**：`state = idle / moving / settling`。轨迹（S 曲线）跑完只代表规划到位，
  进入 `settling`；当 `|pe| < settle_window` 且持续 `settle_time` 后才置 `in_position=True`
  （到位瞬间 `x_actual` 对齐 `pos`、pe 清零，读数稳定）。buffer 步进、工件交接、
  estop 等全部消费 `in_position`，自动继承整定延迟（默认约 50~70ms/次）。
- **回零特例**：回零完成瞬间重定义位置，`x_actual` 直接对齐（pe 清零），
  不让恒速回零段累积的跟随误差拖出假 settling。
- **急停**：pos 冻结后 `x_actual` 继续按一阶滞后泄放，pe 自然收敛到 0，无特殊处理。
- **参数表**（合成经验值，待真机环参数标定）：

| 轴档 | tau（等效位置环时间常数） | settle_window | settle_time |
|---|---|---|---|
| ACS 精密直轴 | 0.005 s | 0.002 mm | 0.05 s |
| 旋转轴（ACS/PLC 同档） | 0.008 s | 20 µrad | 0.05 s |
| PLC 慢速直轴 | 0.015 s | 0.002 mm | 0.05 s |

- **暴露面**：`/api/axes` 每轴新增 `pe / x_actual / state`；`actual` 改为基于
  `x_actual` 叠加误差（errormap 仍按名义值查表，repeat/scale 照旧，两机制正交）；
  WS 108B 二进制帧格式不变（仍发名义值）；`/api/axis/config` 接受
  `tau / settle_window / settle_time`（正数校验，走 config_overrides.json 持久化）。
- **与真机对照**：对应 ACS 的 PE（Position Error）与到位窗口（in-position window）
  语义；真机是三环 PID + 前馈，这里只用一阶滞后近似其**外部可观测时序**
  （巡航段 pe ≈ v·tau、到位有数十 ms 整定延迟），不测控制律本身。

### PLC 扫描周期（`points.py` + `engine.py`，2026-08-19 引入）

模拟倍福 PLC 的周期扫描语义——**写入最多晚一个扫描周期生效，观测以扫描率采样**：

- **映像表模型**：`Points.set()` 只写输入映像（pending 字典，同周期后写覆盖先写）；
  引擎每 `plc_scan_ms` 个 tick（默认 `PLC_SCAN_MS = 4`，合成默认值，真机任务周期待确认）
  调一次 `commit()` 把 pending 合并进输出映像（live）；`get/subtree/snapshot/has`
  全部读 live。注册表外未知点位保持旧语义：set 时立即建档生效（引擎写点位表之外的
  合成观测点用，如气路压强/流量）。
- **内部读点**：引擎联锁/物理逻辑读 live（=上一扫描周期的输出映像，符合真机）。
- **效果**：引擎每 tick 写的观测位（气路 oNegtiveState 等）经 commit 后天然以扫描率
  被 9102 `/io/observe`、9010 `/api/io` 采样；外部写入（SetBool 等）最长 4ms 后被读到。
- **配置**：`POST 9010 /api/plc/scan {"ms": 1~50}`（整数校验），`/api/health` 与
  9102 `/health` 均带出 `plc_scan_ms`；持久化在 config_overrides.json 顶层
  `plc_scan_ms` 键，启动时读取。
- **与真机对照**：对应倍福 TwinCAT 任务周期（典型 1~10ms）；真机还有输入/输出
  映像分离与多任务优先级，这里只建单一周期一档，够联调用。

### 故障注入模型（`engine.py` + 三服务壳，2026-08-19 W2 引入）

目标：让上位机团队能在仿真里**安全地考故障路径**（超时/看门狗/重连逻辑），
复现"下发指令、下位机不回、流程卡死"这类致命现场。

- **每轴使能状态机**：`Axis.enabled`（默认 True）与 `Axis.fault`（默认 False）
  是纯运行时状态，**不进** config_overrides 持久化，重启复位。
  - move/jog/buffer/home 打到 disabled 或 fault 轴 → 拒绝（沿用联锁 409 模式，
    message 为 "axis not enabled" / "axis fault"；9102 同样映射 409，9190 MCS
    映射真机式 FAULT body，9101 回 `{"ok":false}` 行）。
  - **运动中掉使能**（Disable）：轨迹中止，按减速度 `KILL_DEC_FACTOR × amax = 3×amax`
    **自由减速**到静止（每 tick 梯形积分保持位置连续），随后进入 **fault 态**
    （真机掉使能即报警）；`in_position` 不直接置位，交伺服 settling 按 pe 收敛。
    减速度是**合成值**：真机取驱动器 KillDec 量级，本仿真未建模 KillDec 参数，
    故按 3×amax 合成（默认 amax=10×vmax 时 ≈33ms 从满速停，行程 ~10mm 量级）。
  - 静止时 Disable：仅去使能，不进 fault。`ResetError` 清 fault（不改变 enabled，
    真机语义：复位后再 Enable）；`Enable` 复使能并宽容清 fault；
    estop 优先级更高且不变（estop 是全轴急停，不经 enable 状态机）。
- **沉默模式**（`engine.silent`，目标 acs/plc/mcs，复现固件挂死/通讯半断）：
  - HTTP 侧（9102/9190）：请求**挂起不响应**，handler 50ms 轮询等沉默解除，
    60s 兜底回 503 防线程泄漏——客户端只能靠自己的超时发现；
  - 引擎侧：发往生沉默目标的动作指令**被吞**（轴不动、气路 cmd_state 不变、
    回执无异常——"收到但没执行"）；9010 `/api/io/command` 代理对 plc 沉默
    同样吞掉（返回 `ok:true, swallowed:true`）；
  - ACS TCP 9101：连接保持，指令吞掉不回帧。
- **断线模拟**（`engine.dropped` + main.py 故障钩子）：drop = shutdown serve
  循环 + 关 listen socket（新连接 ECONNREFUSED）+ 断开已有连接（真机拔线语义）；
  restore = 重建服务实例重绑端口（bind 失败短退避重试 5s）。钩子注册在 main.py
  （`_srv_holder`），引擎只持函数指针不碰 socket。
- **暴露面**：`POST 9010 /api/fault`（轴使能 `disable/enable/reset_error`；
  目标级 `silent/drop {target,on}`、`restore {target}`；参数非法 400）、
  `GET /api/fault`（全量快照）、`/api/health` 与双端口 `/health` 新增 `faults`
  字段（`{silent, dropped, fault_axes}`）、`/api/axes` 每轴新增 `fault`、
  面板新增"故障注入"区 + 故障横幅。
- **与真机对照**：掉使能语义对齐 ACS 驱动器 Enable/Disable/KillDec/故障报警；
  沉默=固件 main loop 挂死（看门狗未覆盖的场景）或总线半断（收得到回不出）；
  断线=拔网线/断电。三者都是上位机故障路径测试的标准场景。

### 工艺流程编排（`flow_engine.py` + `flows.json`，2026-08-19 W4 引入）

**定位**：这是把将来 **L2 主控层**的活先干了。真机上工艺流程编排属于主控层
（调 L3 Motion/IO 的 RPC）；仿真里 L2/L3 未拆进程，故流程引擎直接调引擎语义层。
等上位机流程定义到位后，`flows.json` 可整体退役，或降级为**回归/演示脚本**
（步骤语义与真机指令面一一对应，脚本本身仍是有效的验收用例）。

- **引擎模型**：单实例挂 `engine.flow`（main.py 启动），独立线程顺序执行；
  **同一时刻只跑一条流程**。状态机 `idle / running / paused / done / aborted`；
  `pause` 在**步骤边界**生效（进行中的步骤跑完），`stop` 立即 abort 并全轴
  stop，`step` 在 paused 态推进一步（`run` 带 `paused=true` 起步即单步模式）。
  状态经 HTTP API 查询（面板 5Hz 轮询），不走 WS 二进制帧。
- **故障联动（W2 的价值兑现）**：estop / 联锁 / 掉使能导致的指令拒绝会使当前
  步骤失败 → 流程 abort，失败步骤与原因进日志；原因尾部自动附当前 fault 轴
  列表。move 等待到位期间轴进 fault 也立即判失败（不傻等超时）。
- **步骤类型表**（op 字段；所有步骤可带 `desc` 中文显示字段）：

| op | 字段 | 语义 |
|---|---|---|
| `move` | axis, target, speed?, timeout?（默认30s） | 发 move 并等 in_position（含伺服 settling） |
| `home` | axis 或 "ALL", timeout?（默认60s） | 回零并等 home_state==done |
| `io` | path, cmd, args? | 走 plc_command 路由（气路/塔灯/光源/温控/电源/互锁全能用）；PLC 沉默时记"被吞" |
| `wait_grip` | circuit, expect, timeout?（默认10s） | 等 grip_ok（真空吸附判定） |
| `wait_io` | path, expect, timeout?（默认10s） | 等任意观测位等于 expect |
| `transfer` | rule, timeout?（默认30s） | 宏步骤：按 transfers.json 规则名执行一次交接——建立接收侧真空 → 姿态轴按文件顺序到示教位（含 settling）→ 来源侧破真空；有 `positive_on_any` 时再发 OpenPositive → 等 die 载体确实变化；超时按当前条件逐项诊断未满足项 |
| `camera` | source（AlignCameraTigger_1/2、AS_CameraOn） | 相机触发拍照记录 |
| `delay` | ms | 延时（可被 stop 打断） |
| `if` | cond:{io:path,expect:val} 或 {grip:circuit,expect:bool}，then:[...], else:[...]? | 条件分支，最多嵌套一层 |
| `log` | msg | 写流程日志 |
| `wafer` | action:"load"/"unload", offset? | 工件上下片（load 幂等：已在位跳过） |

- **transfer 宏与工件层的关系**：只调 workpieces 公开接口（rules_public /
  dies / wafer）与引擎公开指令（air_command / move），不绕开它改内部状态；
  真正的换载体仍由引擎每 tick 的"真空/正压/通大气+示教位"上升沿判定完成——流程层只是
  "把条件凑齐"并验证结果，物理真相唯一。
- **正压/通大气垂直落片（迭代 76/78）**：`head_positive_to_wafer` 用
  `positive_on_any` / `air_on_any` 监听三路键合头真空回路的 OpenPositive /
  OpenAir 指令，任一路即可触发；`site_mode=head_vertical` 按释放时实际 6DOF
  几何与上片误差反算晶圆设计坐标，无流程/高度/晶圆负压门槛。
  `defer_to=head_to_flip` 保证有效翻转承接优先。旧 `head_to_wafer` 规则保留作
  兼容；直接 OpenAir 优先当前 XY 垂直落片。完整 bond 的 `bond_mark` 兼容新旧
  日志，手动落片不生成键合结果。
- **flows.json**：启动加载；`PUT /api/flows` 整体保存（schema 校验：op 合法、
  必填字段、轴名/气路/交接规则/相机源存在性，非法 400 且 `errors[]` 逐条定位
  到 `流程名 steps[i]`）；`POST /api/flows/restore_example` 恢复内置示例
  （内置示例同时是 flows.json 缺失时的播种内容，单一事实源在 flow_engine.py
  `EXAMPLE_FLOWS`）。
- **内置示例"晶圆键合示范流程"**（19 步）：log → wafer load → transfer
  film_to_flip（取片）→ **AS_Y→+120 退避对准台相机 + WS_LS_X→+220 退避
  晶圆台** → transfer flip_to_head（键合头接管）→ AS_X 对准扫描 + camera×2
  → **BS_Arm_Z→0 抬头 → WS_LS_X→0 晶圆台回零** → transfer head_to_wafer
  （键合）→ 键合臂抬起 → **AS_Y 回零** → FA 两轴回安全位 → wafer unload
  → log。
  交接坐标全部引用 transfers.json 示教位（占位待标定，流程 description
  已注明）；对准台扫描幅值 ±20mm 沿用 ACS buffer2 align_scan 占位值。
  两组退避编排都是 2026-08-20 零件级沙盒复盘后加的：真机流程本就
  "先退避 AS 相机再降键合头"；晶圆台回零前必须先抬头（低位臂会挡
  回位通道被 409 拦），零件级对表把这些回避动作全部逼成了显式步骤
  （见下节"沙盒干涉检查"）。
  实测总耗时约 10.9s，die 迁移路径 film→flip→head→wafer→随片下机。

### 沙盒干涉检查（`collision.py` + `sandboxes.json`，2026-08-20 W5 引入，
### 同日 v2 零件级重构）

**定位**：真机的防碰靠"机械限位 + 软件禁区（safe zone）+ 力控接触段"。
本仿真实现的是其中的**软件禁区**——以前端 TwinDOM 模型（已装配整机）各
零件的沙盒（AABB 包围盒）为准，两盒**穿模深度**（三向重叠量的最小值，
="拔出最少要走多远"）> ε 即判干涉。

- **数据源**：`tools/gen_sandboxes.py` 解析 `html_model/d2w_front.json`
  （只读原文件），输出 `runtime/sandboxes.json`（schema 2，模型更新后重跑
  脚本即可）。盒定义 = 零位世界 AABB；几何映射：Box/RoundedBox 的
  width/depth/height ↔ X/Y/Z（Z 向上），Cylinder/Lathe 回转体取半径外接，
  Extrude 轮廓在 XY、depth 沿 Z，Ring/Circle 平面几何给 0.5mm 兜底厚度。
- **零件级粒度（v2 的核心改动）**：v1 按"轴 movingObject 子树聚合盒"成盒，
  一个运动盒把吸盘、气环、导轨全揉在一起——盒间一旦相擦，要么整对豁免
  （吞掉真穿模，2026-08-20 用户实测漏报的根因），要么整对报警（误报）。
  v2 改为**每个几何体一个零件盒**（`pt:<objectId>`），盒带 `group`
  （归属的运动组 `grp:<movingObjectId>` 或 `fixed`）与中文 label
  （`零件名〔组名〕`，409 报文和面板横幅直接可读）。配对只在**跨组**
  之间查：组内零件相对静止永不互撞，固定×固定不查。
- **判撞口径 ε=2mm**：两盒三向都重叠且最小重叠深度 > depth_eps（默认 2mm）
  才判撞。依据：工艺接触段要容忍晶圆厚度 0.7mm + 压合贴合 ~1mm 量级的
  贴面重叠；结构件厚度均 ≥3mm，真穿模（嵌进对方结构件）深度必超 ε。
  推论：**薄片穿刺不报警**——压头/吸盘唇/蓝膜等 ≤1.2mm 薄片，穿模深度
  永远超不过自身厚度（≤ε），拦"深降"靠的是气环、吸盘基座、台体等厚件；
  这与真机"力控管接触、机械限位管结构"的分层一致。阈值可在线调：
  `POST /api/collision {depth_eps}`（[0,50]mm，非法 400；调小立即变严，
  缓存自动重建）。
- **旋转轴简化**：不做逐帧旋转精确盒——生成期把零件零位盒按轴行程扫掠成
  **旋转不变盒**（±180° 的 FA_Rx/CH_Rz 零件 ≈ 圆柱外接盒；±0.1° 的校准轴
  几乎不膨胀），运行时旋转轴零开销。代价：保守外扩会把"翻转到某角度才
  撞"误判为"恒可能撞"（FA_X 深行程禁区阈值 ≈-1086mm 即由扫掠盒触发）。
- **对表与豁免**：跨组 C(n,2) 对子在生成期筛到只剩有效对——纯旋转相对
  静止剔除、**轴包络恒不相交**剪枝（三维任一可达包络不相交则永不撞，
  7994 对）、**零位设计贴合**自动豁免（零位跨组重叠深度 > ε = 装配嵌套/
  贴合，如顶针导轨×台体、吸盘×座，逐对打印进生成报告供人工复审，33 对）、
  **工艺/设计接触**显式豁免（PROCESS_EXEMPT 2 条规则 = 7 对：Epin 顶针/
  片压×多孔陶瓷面——顶出晶圆走过孔/沉孔，AABB 无孔概念；对准台X/Y轴承
  承接板——层叠滑台副，AS_Z 行程内结构交叠，真机槽/孔让位 AABB 不可见）。
  实测：146 盒（运动 93 / 固定 53，18 运动组）→ 872 有效对（其中 70 对
  hit_axes 非空）/ 40 豁免 / 7994 剪枝。
  注：对表里的 `hit_axes` 只是生成期"哪根轴能撞上这对"的**信息标记**
  （单轴全程采样，≤2mm 步长——三点采样曾漏掉 Epin 片压穿陶瓷面的窗口型
  重叠）；运行时判定不走 hit_axes，而是从盒的 linear 贡献建轴→对索引。
- **v1→v2 穿模漏报复盘（2026-08-20）**：v1 时代豁免清单按聚合盒对对
  豁免，曾把"键合头链×对准相机承载台"整对豁免（理由"键合行程贴相机位"），
  实测吞掉真穿模；移除该条后用户仍实测漏报三处（键合头×晶圆台、键合头
  ×对准台、翻转Z×蓝膜台）——根因是**聚合盒粒度**：盒内零件高低不齐，
  聚合盒相擦 ≠ 零件相碰，报警/豁免都无法给到正确粒度。v2 零件级后三处
  场景全部成为回归用例（test_client.py test_collision）：
  ① 退避 AS 后 BS 降到 -162.5 键合接触位放行、再深降气环埋进吸盘基座 409；
  ② 对准台零位 BS 降到气环贴承载台面（重叠 1mm<ε）放行、再深降 409；
  ③ FA_Z=-5 贴膜放行、压进蓝膜台体 409。示教位同步反推修正：
  film_to_flip FA_Z [-38,4]→[-5,3]（芯片吸盘扫掠盒底 z=891.6 贴蓝膜面
  886.9）、head_to_wafer BS_Arm_Z [-188,8]→[-162.5,8]（吸盘底 1053.83
  贴吸盘基座顶 891.9），仍是占位待真机标定。
- **运行时两条链**（engine.py，复用联锁 409 语义，侵入最小）：
  - move 起步检查：目标位代入对表评估，深度>ε → `InterlockError`
    （9102/9010 映射 409，错误消息列前 3 对零件级盒名 + 总对数；buffer
    步骤被拒则 buffer 中止，流程步骤被拒则流程 abort——W2/W4 的故障
    联动自动继承）。
  - tick 检查（500Hz，每 2 tick）：纯增量——轴位置没变的盒不重算、不碰
    脏盒的对不复查；新撞入 → **全轴 soft-stop**（与门开同语义）+ 事件记录
    （对子/时刻/被停轴，环形 50 条）。已在重叠中的对（move 起步时存在的）
    进 tolerated 集合，**允许从重叠区回撤**，退出后自动解除容忍。
- **总开关**：`GET/POST /api/collision`（`{enabled, depth_eps?}`，默认开、
  ε=2mm）；关闭期间形成的静止重叠在重开后只报告（active 列表）不追溯停。
  状态进 `/api/health` 的 `collision` 字段（enabled/loaded/boxes/pairs/active）。
- **观测面**：`/api/collision` 返回盒/对统计 + 当前重叠对 + 近期事件；
  面板顶部第三条横幅（紫色），复用联锁横幅样式，2Hz 轮询——零件级 label
  自动流入，无需面板改动。
- **性能**：872 有效对 + 增量检查，tick 内开销实测无感（health 红线
  tick 1000Hz / push 500Hz 无退化，见交接文档本轮条目）。
- **遗留风险**（生成报告与回归均确认）：
  - Epin 顶针组模型把 z 向导轨/滑块也建为随组上升（真机导轨固定），
    Epin≥+10 会撞吸盘基座、+30 撞陶瓷面——**保留报警**（模型伪影，
    前端模型修正后重跑 gen_sandboxes.py 即消失）；因此仿真里 Epin
    可用行程只有 [0, +9] 左右，回归用例按 +5 验证；
  - 顶针×台体等 33 对零位设计贴合豁免同时掩盖了"ES_Y 带针横移"这类
    动作的同对重叠（豁免是对级、无方向性）；
  - 压环类 1.5mm<ε 的薄件穿越不报警（ε 语义的既定代价，厚件兜底）；
  - 交接示教位仍是几何反推占位，待真机标定。

## 2. 和真机一样吗？——不一样，而且要知道哪里不一样

| 维度 | 真机 ACS（SPiiPlus 平台） | 我们的模拟器 |
|---|---|---|
| 通讯 | 厂商 SDK（TCP/IP，私有协议；SPiiPlus 同时是 EtherCAT 主站） | 自定义 JSON-lines TCP（**过渡协议，待真协议资料**） |
| 控制核心 | kHz 级伺服三环（电流/速度/位置环）、PID 整定、前馈、误差补偿表 | 无伺服环，直接按规划轨迹积分（理想跟随）+ 读取时叠加误差 |
| 回零 | CiA402 语义（17/18=负/正限位开关，EtherCAT CoE 驱动 profile）| **同语义**的状态机 + 虚拟限位开关 |
| buffer | ACSPL+ 语言编写的控制器内程序 | Python 写的预置运动序列，语义等价 |
| 单位/精度 | 编码器计数，nm 级 | 浮点 mm/rad，接口层 nm 级显示 |

| 维度 | 真机 PLC（倍福 Beckhoff） | 我们的模拟器 |
|---|---|---|
| 硬件 | EK1100 耦合器 + EL1889/EL2889（DI/DO）+ EL3208/EL3314（温度）+ EL5042（BiSS）等 EtherCAT 端子 | 无硬件，点位状态表 |
| 通讯 | TwinCAT 原生为 **ADS 协议**；你们项目是"HTTP 和 PLC 通讯"（具体报文待确认 Q4，可能是自研 HTTP 桥） | 自定义 HTTP REST（过渡协议） |
| 扫描 | ms 级周期任务，GVL 全局变量 | 1kHz tick 内更新点位，同名 GVL 变量 |
| 气路物理 | 真实阀岛/管路动态 | 一阶惯性近似（足够做联调和演示，不是气动仿真） |

**一句话**：我们仿真的是各层**外部可观测行为**（指令→轨迹→反馈的语义与时序），不是内部控制律。对"上位机联调、流程验证、3D 可视化"这个目的，外部行为保真就够了。

## 3. 调试好之后，代码能不能直接用到真实设备上？

**仿真核（engine/轨迹/误差/点位物理）不能、也不需要搬到真机上**——真机的 ACS/PLC 本身就是"真的物理引擎"。

**可以直接复用/迁移的部分**（这正是分层架构的意义）：

1. **3D 联机模型和轴控面板**：把 WS/HTTP 的适配层指向真机数据源（真 ACS 的轴位置反馈、真 PLC 的点位），前端零改动——数字孪生的标准用法；
2. **接口契约与点位数据**：`接口规范_V1.md`、`io_points.json`、21 轴配置（行程/速度/回零方式）——这些是从点位表整理的事实资产，直接就是联调依据；
3. **工艺动作序列**（将来 L2/L3 层做的流程编排）：如果按点位表的 Command/Observer 语义写，流程逻辑可原样迁移到真机主控；
4. **验证过的交互逻辑**：面板和 3D 的操作语义（回零流程、限位行为、误差显示）在仿真里调好，真机联调时就是验收基准。

迁移路径（将来）：`面板/3D → [协议适配层] → 真 ACS SDK / 真 PLC HTTP`。适配层是唯一要新写的部分，厚度取决于 Q1~Q4 的答案。

## 4. 关于"SEMI 标准"的澄清

SEMI 标准（E5 SECS-II / E30 GEM / E40 等）规范的是**设备与工厂主机（MES）之间**的通讯，在金字塔最顶端 GUI 之上，与设备内部的轴控/回零无关。回零和驱动行为的事实来源是 **CiA402（EtherCAT CoE 驱动 profile）**——ACS 作为 EtherCAT 主站，其轴回零方法编号（17/18）正是 CiA402 语义，我们已按此实现。若将来要对接 MES，再引入 SECS/GEM 层，当前阶段不需要。
