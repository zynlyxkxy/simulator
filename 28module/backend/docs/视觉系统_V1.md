## 1. 架构

```
 PLC 9102 SetBool ──► engine.camera_trigger ──► VisionService.notify_trigger
 (AlignCameraTigger_1/2,      (锁外 queue.put_nowait,        (8 深队列,满丢最旧)
  AS_CameraOn; 或 API 软触发)   绝不阻塞 1kHz 物理线程)
                                                    │
        ┌───────────────────────────────────────────▼──────────┐
        │  相机线程 ×3（coarse/up/down，互不影响）               │
        │  trigger: 光源灭→points.set 点亮(吃 4ms PLC 扫描)      │
        │           →等曝光 exposure_ms→按帧时刻轴位+误差渲染     │
        │           →光源灭→处理发布                             │
        │  continuous: 光源常开持续出图(REAL 节流 ~5Hz live 帧)  │
        └───────┬───────────────────────────────┬──────────────┘
                │ FAST                            │ REAL(默认,迭代17起)
                │ vision_model 解析投影           │ render_frame(numpy+cv2)
                │ 直接合成同 schema 结果          │ → raw灰度帧 → TCP ──► 9200
                │                              │    接收线程解帧 → cv2 NCC
                │                              │    模板匹配+全分辨率亚像素
                │                              │    +几何角连续化(迭代23)
                ▼                              ▼
        结果 {strShapeName,judge,lstCol,lstRow,lstAngle,lstScore,lstScale}
                │                              │
                └──────► mqtt_publish ──► broker 1883 topic vision/result/{cam}
                       完整记录(含耗时分解) → 环形缓冲 100 条 → /api/vision/results
```

线程红线：渲染/传输/匹配/MQTT 全部在 vision_service 自己的线程；物理引擎
只做非阻塞队列通知。回归 `vision.perf_guard` 断言 tick≥999Hz / push≥499Hz。
**OS 线程优先级分离**（2026-08-21 下午加固，ctypes 标准库）：物理线程
`THREAD_PRIORITY_HIGHEST`（engine.run 起始自提），视觉全部线程
（accept/recv+匹配/相机×3/光源跟踪）`THREAD_PRIORITY_BELOW_NORMAL`，
且匹配精化每迭代、NMS 每实例、渲染每标记 `time.sleep(0)` 让出 GIL——
REAL 匹配的大量小 cv2 调用不释放 GIL，同优先级下会稳定压制 1kHz 物理
忙等线程（perf_guard 贴线根因）。注意 ctypes 调 `GetCurrentThread` 必须
`restype=c_void_p`：默认 c_int 会把伪句柄 -2 零扩展成 0xFFFFFFFE，
`SetThreadPriority` 静默失败（返 0，已实测验证）。

## 2. 端口

| 端口 | 服务 | 说明 |
|---|---|---|
| 1883 | 迷你 MQTT 3.1.1 broker（runtime/mqtt_broker.py） | CONNECT/SUBSCRIBE(含 `+`/`#` 通配)/PUBLISH QoS0（QoS1 回 PUBACK 后按 QoS0 投递）/PINGREQ/DISCONNECT；仅本机回环。**只认 3.1.1/v4**：MQTT 5 客户端（MQTTX 默认）被 CONNACK rc=1 拒，改 3.1.1 即可（2026-09-21 实测） |
| 9200 | 视觉服务 TCP 图像接收口（runtime/vision_service.py） | 相机线程真 socket 推帧，接收线程解帧+匹配；帧格式见 §3 |

两个端口均不用 SO_REUSEADDR（与既有三端口同惯例：Windows 双绑定会随机
分流到旧进程，跑测试前先 `netstat -ano` 清残留）。

## 3. TCP 9200 帧格式（相机 → 视觉服务，大端）

```
[4B BE json头长][json头][4B BE 图像字节长][图像字节]
```

json 头字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| cam | str | `coarse` / `up` / `down` |
| w, h | int | 图像像素尺寸（REAL 全幅 3000×3000；live 预览 640×480） |
| enc | str | 图像编码（2026-09-05 迭代 17 起）：`"raw"`=直接灰度字节（w×h 字节，免 PNG 编解码，REAL 内部链路默认）；缺省/`"png"`=PNG 字节（旧兼容，live 帧仍用 PNG） |
| t | f64 | 发送时刻 epoch 秒 |
| sim_t | f64 | 仿真时钟秒（帧采样时刻） |
| seq | int | 结果序号（live 帧为 0；match=true 的帧与结果 entry.seq 对应） |
| match | bool | true=接收侧需对该帧做模板匹配并回结果 |
| frame_seq | int | 该相机推帧累计序号（含 live 帧，调试用） |
| axes | obj | 帧时刻相关轴位快照 `{轴名: 值}`（mm/rad，4 位小数） |

编解码：`encode_frame(header, data)` / `read_frame(conn)`（vision_service.py
顶部）。enc=png 时图像为 stdlib 自写 PNG 编码器（8bit 灰度，zlib level 1）
产物，`cv2.imdecode` 可直接解；enc=raw 时 `np.frombuffer(...).reshape(h,w)`。

## 4. MQTT 结果契约

| topic | 载荷 | 时机 |
|---|---|---|
| `vision/result/coarse` | 七字段 JSON（UTF-8，ensure_ascii=False） | 该相机每次出结果（触发/软触发/identify，FAST 与 REAL 同） |
| `vision/result/up` | 同上 | 同上 |
| `vision/result/down` | 同上 | 同上 |

七字段 schema（对齐上位机视觉结果惯例；2026-09-02 迭代 11 起追加第 8 字段
`lstName` 见表末行），耗时分解等元数据不进 MQTT，只在结果环形缓冲 /
identify API 响应里：

| 字段 | 类型 | 说明 |
|---|---|---|
| strShapeName | str | **2026-09-05 迭代 16 起 = 本次触发模板名**（真实视觉软件按模板名启动/回查识别）：单模板为模板名本身（如 `cv_quad`，无括号/后缀）；多模板（键合后红外套刻双模板列表）为 `"+"` 连接（如 `tpl_post_inspect+cv_quad`）。无 template 的旧式触发（硬触发等）保留旧回退：FAST=首个在 FOV 场景标记的形状名（`cross`/`box`/`circle`/`quad`），REAL=该相机首个模板的 shape/名；无标记/出错为 `""` |
| judge | bool | 总判定：有标记且最高分 ≥ 阈值且未被判废（离焦超 3×DOF 等） |
| lstCol | [f64] | 各标记质心图像 u（像素，图像系 u 向右），亚像素精度 |
| lstRow | [f64] | 各标记质心图像 v（像素，v 向下） |
| lstAngle | [f64] | 各标记角度（度，图像系内相对模板/名义朝向） |
| lstScore | [f64] | 各标记得分 0~1（REAL=NCC 峰值；FAST=按噪声/离焦衰减的合成分） |
| lstScale | [f64] | 各标记比例（REAL=精化出的比例因子；FAST=1.0±噪声） |
| lstName | [str] | **2026-09-02 迭代 11 起追加的第 8 字段**：各条目来源标记名（FAST=场景标记名，如 `site_R01C02#0` / `R03C04#2`；REAL=命中模板名）。键合后精度检测（post_inspect）按名筛 die 标记（`die_id#k`）消费；旧消费者忽略即可（其余七字段不变） |

数组等长（多标记时逐个一行，上限 16，按得分降序）；空结果各数组为空。

结果环形缓冲 entry（`/api/vision/results`、identify/acquire 响应的 `entry`）：

```json
{"seq": 12, "t": 1724…, "sim_t": 45.21, "cam": "down",
 "source": "AlignCameraTigger_2 | api | identify",
 "mode": "fast|real", "light_on": true, "flash": true,

               "in_dof": false}],
```

**模板名来源（2026-09-04 迭代 12 起）**：每次触发相机拍照必须依据模板名
识别标记——流程侧全部拍照点（coarse_offset / ega_measure / fl
align_first / fa_measure 双侧 / pi_measure）的模板名一律取**机械常数
`vision_marks` 组**（`machine_constants.json`，flow_engine `_vision_tpl`
按用途取键：`tpl_wafer_site` 下相机晶圆 site 标记、`tpl_coarse_die`
coarse 相机翻转吸盘 die 背面、`tpl_die_head` 上相机键合头 die 角标、
`tpl_head_chuck` 上相机吸盘标记（as_head_center 测校预留）、
`tpl_post_inspect` 下相机键合后红外透视 die 角标）；缺配即步骤失败。
视觉服务侧 FAST/REAL 两模式都做**模板存在性校验**：指定模板不在
`vision_templates.json` 中报"模板未建立"（模拟真机未建模板不能识别），
识别结果 entry 与 MQTT 结果载荷附 `template` 字段供流程日志溯源。

`surfaces`（2026-08-21 分层景深起）= 当前 FOV 内可见的**表面层**景深状态
（`surfaces_public`，见 §7）：每层 `{name, z_mm, defocus_um, in_dof}`，
defocus_um = (层Z−焦面Z)×1000，in_dof = |defocus_um| ≤ dof_um；只收
FOV 可见层（层几何像素 bbox 与画幅相交判定），按回→前层序排列。

**红外套刻通道 ir_overlay（2026-09-05 迭代 15，仅下相机 wafer_marks
源；迭代 20 起流程改两次独立触发）**：post-inspect 套刻的采集模型。
触发侧 `vision/trigger/{cam}` 载荷可带 `"ir_overlay": true`（template
同时可传**模板名列表**，如 `[tpl_wafer_site, tpl_post_inspect]`——
FAST/REAL 逐个做存在性校验，REAL 按列表逐模板匹配；**契约保留，但
迭代 20 起 pi_measure 流程不再用列表：同一机位两次独立触发，先 quad
模板后 cross 模板各带 ir_overlay**——用户实测工艺语义）；entry/MQTT
载荷回附 `"ir_overlay": true` 与触发时形态的 `template`。语义
（vision_model `collect_marks`/`collect_layers` 的 ir_overlay 分支，
**可见光通道 EGA/调平/精对准不受影响**）：

- 被键合 die 覆盖的 site 对准标记（quad）**恢复可见**（可见光下物理
  遮挡；IR 穿透一个芯片厚度）；
- wafer_die 层 die 角标（cross）的 z 按**晶圆面**计（IR 假设：焦面=
  晶圆面（下芯片表面）时，晶圆面 quad 与 die 角标 cross 在同一画幅
  内都算合焦——远心投影 z 不影响 (x,y)，clamp 只改离焦量；REAL 渲染
  wafer_die 层 z 同样按晶圆面计，两层同焦清晰）；
- **REAL 渲染 die 本体不遮光**（2026-09-05 迭代 17 修复：原回→前绘制
  序让 wafer_die 层 die 本体盖住 wafer 层 quad、且 cross 按 z 并列时宿主
  判到 wafer 层也被一并盖没，REAL 套刻帧两个标记全不可见；现 ir_overlay
  下 wafer_die 层只画 cross 标记不画本体；空 items 层的离焦模糊 bbox 由
  宿主标记投影像素补上）；
- **多标记覆盖率并集绘制**（2026-09-21 迭代 53 修复）：标记精灵 warpAffine
  旧实现是**整窗替换**——套刻对相距 ~21px ≪ 绘制窗半径 128px，后画的
  cross 窗口把先画的 quad 覆盖率整窗清零（quad 只剩右缘细条、NCC 全灭、
  REAL pi 自迭代 35 起静默失效六个迭代）；现 warp 进暂存后 `cv2.max` 并入，
  窗口重叠区取覆盖率并集（非重叠标记零行为变化）；
- 一张图形成 quad⊕cross 套刻图：site 的 quad（下芯片侧）+ die 的

对焦三字段（FAST/REAL 同带；`focus_err_um`/`blur_ratio` 取最靠近光轴的
目标标记，无标记时为 null）：

| focus_state | 含义 | 判定 |
|---|---|---|
| `in_focus` | 在景深内 | blur_ratio ≤ 1 |
| `defocused` | 离焦未判废 | 1 < blur_ratio ≤ 3 |
| `rejected` | 离焦判废（judge=false 同语义） | blur_ratio > 3 |
| `no_mark` | 视野无任何标记（无工件/载体空） | 几何事实，优先于灯态 |
| `light_off` | 有标记但光源灭（暗图必废） | 次于 no_mark |

判定优先级：`no_mark` > `light_off` > blur 分档。拍帧异常（error 字段有
明细）的 entry 三字段一律 `null`。`GET /api/vision/cameras` 每相机也带
现算的 `focus_err_um`/`in_dof`/`focus_state`（灯态取当前光源，trigger
待机灯灭时为 `light_off`）与 `surfaces`（同上 schema，现算）。

**结果载荷外包与认领（2026-09-10 迭代 31 增补）**：MQTT 结果载荷外包为
`{req_id, cam, result:<七字段>[, error][, template]}`——`cam` 迭代 31 起

认领——只按 req_id 认领会跨相机串答。未知相机触发有 req_id 时回 error
帧到同名结果 topic（不再静默丢弃）；连续看画面用 continuous+灯常开或
HTTP frame 预览，禁止循环触发当 live（每触发一次=一次完整频闪）；结果
超时建议 30s（REAL 单拍 0.6~1.6s+多相机串行）；9200 为相机→视觉服务
内部图像口，外部软件不可连不可绑；模板须先建进模板库再按名触发。详见
《前后端数据协议_V1.md》§9"无全局触发契约"。

## 5. 相机模式与触发闪光时序

每相机独立两模式（`POST /api/vision/camera/config {"cam","mode"}`）：

- **continuous**：光源常开持续有画面；REAL 下内部节流 ~5Hz 推 live 帧到
  9200（不匹配）。灯亮时 identify/acquire 直接拍当前帧（无闪光）；
  **灯灭时 identify 走判废路径**（暗图，不替你闪光——真机语义：常开模式
  下灯灭是工况异常）。
- **trigger**（默认）：闪光链路——
  1. 触发源：PLC 9102 `SetBool true` / `Pulse` 打到
     `SystemMachine.SS_Bonding.M_AS.{AlignCameraTigger_1, AlignCameraTigger_2,
     AS_CameraOn}`（点位表原名，Tigger 拼写沿真机），或
     `POST /api/vision/acquire`（软触发，source="api"）、
     `POST /api/vision/identify`（source="identify"）。
  2. 关联光源若灭 → 视觉线程 `points.set` 点亮命令点（写 `M_AS.LightOn_*`，
     吃一个 PLC 扫描周期（默认 4ms）镜像到 `oLightOn_*` 观测点——闪光观测
     与真机同语义）；已亮则不重复点。
  3. 等曝光 `exposure_ms`（墙钟）。
  4. 以**帧时刻的轴位 + 6DOF 误差位姿**渲染采样。
  5. 闪光由本服务点亮的 → 拍后熄灭；常亮的不动。
  6. 处理（FAST 解析 / REAL TCP+匹配）→ MQTT 发布 + 入环形缓冲。

引擎侧 `engine.camera_trigger()` 原有行为保留（captures 轴位快照记录照记，
`/api/camera/captures` 不变），尾部追加非阻塞 `vision.notify_trigger()`。

## 6. 相机参数（内参=机器常数，2026-08-21/24 起真实光学+传感器数据）

**存储结构（单一事实源）**：相机**内参**（pixel_um/mag/dir_x/dir_y/
swap_xy/rot_mrad/wd_mm/dof_um + **px_u/px_v 传感器分辨率**）统一存
`runtime/machine_constants.json` 的 cameras 组——由 machine_constants.py
加载并全量校验（坏配置拒绝拉起）；GET/PUT `/api/machine_constants`
在线改 + 原子落盘 + 视觉侧热生效，派生量 k_um_px/fov_x_mm/fov_y_mm 只读
不落盘（GET 时按 px_u/px_v 现算）。**px 分辨率 2026-08-24 自
vision_cameras.json 迁入并更名 px_u/px_v**（用户："像素值也要放到机械常数

  bbox 内已合成的后层内容一并承受本层 σ（本机相邻面间距 ≪DOF 时 σ
  接近，无可见伪影）。**surfaces 字段**（`surfaces_public`）：
  cameras_public 与 identify entry 每相机带 `[{name, z_mm, defocus_um,
  in_dof}]`，只收 FOV 可见层（层几何像素 bbox 与画幅相交判定），
  defocus_um=(层Z−焦面Z)×1000，in_dof=|defocus_um|≤dof_um。
- FAST 模式解析投影器直接合成七字段（位置噪声 0.15px、blur>1 得分平方
  衰减封顶 25×、blur>3 判废），结果 schema 与 REAL 完全一致；FAST 不渲染
  大图（场景管线只服务 REAL 帧与 live 预览）。

证实后修正）。修复后验证：连续 3 次全量回归 200/200，perf_guard 实测

164.5~215ms（GIL 争斗消除后匹配段本身也变快变稳），基本稳达 brief 的
<200ms。预留备案（未实现，需要时再加）：匹配窗口降采样 `proc_scale`
（0.5 倍，像素坐标按 1/proc_scale 映射回原图）——本轮 1+2 已够，不动
vision_cameras.json schema。

### FAST vs REAL 结果语义对照表（2026-09-05 迭代 17 增补）

七字段 schema 两模式完全一致（§4），但字段语义来源不同：

| 字段/面 | FAST（解析投影） | REAL（OpenCV 全链路，默认） |
|---|---|---|
| judge | `in_fov 且 blur≤3 且灯亮`（几何/离焦/光源判定） | `score ≥ threshold`（NCC 峰值过阈；暗图/离焦图经 NCC 低分自然判废，不看灯位/离焦量本身） |
| lstCol/lstRow | 解析投影 + 0.15px 噪声（离焦平方放大封顶 25×） | 全分辨率开窗 NCC + 3×3 抛物线亚像素（迭代 23 起；仅过阈值峰精化，大模板/失败回退粗网格亚像素，原峰位只进 entry 调试字段 ncc_col/ncc_row，不进 MQTT） |
| lstAngle | 标记投影后 +x 轴的图像角（含相机安装角，连续值） | 几何角=环形扇区灰度加权质心星座连续角（迭代 23 起，取代 0.2° 量化网格；失败回退 NCC 粗扫+抛物线锚点量化角） |
| lstScale | 恒 1.0（±噪声） | 恒 1.0（比例精化默认关 `Matcher.refine_scale=False`，仿真相机正交俯视 scale 恒 1.0） |
| lstName | 场景标记名（`site_R01C02#0` / `R03C04#2` 等） | 命中模板名（无 `#k` 后缀） |
| strShapeName | 两模式一致 = 本次触发模板名（迭代 16 契约）；仅无 template 旧式触发回退不同（FAST=首个在 FOV 场景标记的形状名，REAL=该相机首个模板 shape/名） | 同左 |
| in_fov（entry 内部字段） | 按投影真实判定（FOV 外条目不出的七字段） | 恒 True（NCC 命中即在视野） |
| blur（entry 内部字段） | blur_ratio 真值 | 恒 0.0（离焦由 NCC 低分间接体现） |
| 入口校验 | 模板存在性校验两模式相同；REAL 额外要求 cv2 可用、无模板 400 | 同左 |

消费者（flow_engine 各拍照点、calibration）只读 result 级
lstCol/lstRow/judge/lstAngle/lstName，两模式字段齐备，无缺失风险。

## 11. 已知占位与限制

- 相机 WD/DOF/pixel_um/mag 已是真实光学+传感器数据（§6，2026-08-21/24）；
  dir 默认已对齐真实相机朝向（迭代 35，三相机统一 (+1,−1)）；rot_mrad 为
  控制器认知占位待重标定（真值在 vision_cameras.json view_rot_deg；可用
  rotation_direction/camera_microrot 测校程序实测写回）。
- 3D 模型里画出的相机外壳位置是 CAD 占位（coarse 外壳 z≈1181），视觉
  仿真镜头位置以 machine_constants.json + vision_cameras.json mount 为准。
- REAL 匹配 total 164.5~215ms（GIL 修复后，§8），基本稳达 <200ms；红线 tick/push 连续 3 次回归实测满分。
- 渲染为灰度几何图（无材质/畸变/杂散光）；场景层为固定比例灰度
  （SCENE_* 合成值待真机标定），渐晕是简单乘性模型；陶瓷面按"恒大于
  FOV"整帧铺满不建边缘模型，真空气路纹路为合成常量图案（间距/槽宽/
  灰度比均待真机标定）；离焦层模糊按内容 bbox 贴回（无逐像素 alpha
  mask），相邻面 σ 差异大时 bbox 内后层内容会同档糊化（本机层间距
  ≪DOF，实际不可见）。
- live 预览固定 640×480 降采样，非 sensor 原生分辨率链路。
- cv2/numpy 为可选依赖：缺失时 REAL 报清晰错误（400），FAST 全功能可用
  （回归 cv2 缺失时 real 用例 skip 不 FAIL）；测校三程序同样依赖 cv2。
- MQTT broker 为迷你实现：无 retain、无认证，仅本机回环用途；QoS2 自
  迭代 37 起完整支持（PUBREC/PUBREL/PUBCOMP 四段握手、PUBREL 时刻恰好
  一次转发、重复/迟到重发去重，见 runtime/mqtt_broker.py 模块注释）。
- 模板 ROI 只支持轴对齐矩形；多角度/多尺度模板未做。
