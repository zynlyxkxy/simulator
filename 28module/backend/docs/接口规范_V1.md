# D2W 键合设备全链路仿真 — 接口规范 V1

> 状态：**草案（仿真侧自定义，待与上位机对齐）**
> 日期：2026-10-21（迭代 76 更新工件交接规则）
> 事实来源：`1928运动固件点位表_V10.xlsx`（下位机提供，唯一已确认资料）、`硅片台模块轴记录表.xlsx`、`d2w_front.json`（TwinDOM Studio 导出，164 对象 / 20 轴）

## 0. 本文档的目的与用法

上位机（GUI 软件）尚在开发，接口资料拿不到。本规范的做法是**契约先行**：

1. 仿真各层之间先按本文档的自定义协议开发，不阻塞进度；
2. 命名**严格沿用点位表中的 Cordis 侧变量路径**（`SystemMachine.SS_*.M_*`），这些名字是下位机已定的事实，上位机大概率沿用——届时对齐工作量最小；
3. 所有"不确定、待上位机确认"的条目集中在 **§7 问题清单**，开发中持续补充，上位机接口出来后逐条核对、只做映射层适配，主体不返工。

## 1. 真机通讯架构与仿真层对应

```
第一层  设备GUI软件（同事开发中）        ← 最终直接连我们的第二层模拟器
           │ RPC（技术栈未知，待确认 Q1）
第二层  主控单元（流程封装/设备功能）     ← 模拟器：工艺流程编排 + 状态管理
           │ RPC（待确认 Q2）
第三层  Motion 和 IO                   ← 模拟器：指令翻译/队列/互锁
           │ SDK TCP (Motion)  │  HTTP (IO)
第四层  ACS（运动控制器）  PLC（IO）    ← 模拟器：TCP 服务 + HTTP 服务
           │                            内含轨迹规划 + 轴状态积分 + 点位状态
           ▼
        真实轴/点位（无硬件 → 纯软件仿真）
        + 3D 前端模型（订阅第四层轴位置做可视化）
```

参考项目（d2w_sim / backend）把第二~四层压在一个进程里，只适合借鉴**层内算法**（S 曲线轨迹、轴状态积分、生成器式流程编排）；**层间通讯按本文档协议实现**，进程边界与真机一致，任何一层将来都可被真机部件替换。

## 2. 命名规范（核心约定）

点位表已经定义了三层命名，仿真全部沿用：

| 层 | 命名示例 | 说明 |
|---|---|---|
| 上位机/Cordis 侧 | `SystemMachine.SS_Bonding.M_WS.iZeroEpin_Z` | **本规范的主命名**，接口与代码内统一使用 |
| PLC 侧 | `GVL_IO.iSystemOn` | PLC 模拟器内部变量名 |
| ACS 侧 | 轴名 `WS_LS_X` / buffer 号 | ACS 模拟器轴标识 |

子系统前缀（点位表既有）：

- `SystemMachine.SS_Bonding.M_WS` — 硅片台模块（Wafer Stage）
- `SystemMachine.SS_Bonding.M_BS` — 键合模块（Bonding）
- `SystemMachine.SS_Bonding.M_AS` — 对准模块（Alignment）
- `SystemMachine.SS_Bonding.M_ES` — 蓝膜台模块（外包，高层命令接口）
- `SystemMachine.SS_CH.M_FA` / `M_CH` — 芯片传输分系统（翻转模块等）
- `SystemMachine.SS_ME.M_AIR` — 气控箱
- `SystemMachine.SS_ME.M_PowerSwitch / M_InterLock / M_EMO / M_SLAM / M_Voltage_Warning` — 系统层（电源/门锁/急停/灯塔/电压）
- `SystemMachine.M_Heater.*`、`SystemMachine.M_ACS_Buffer.*` — 温控、ACS buffer

**Command / Observer 配对模式**（点位表既定事实，全接口遵守）：

- 命令（写）：动词方法或 `oXxx` 对应的 Command 入口，如 `M_AIR.WT_WaferVac.OpenPositive / OpenNegtive / OpenAir`、`M_BS.BondingByForceManual(Real Force, Real Speed)`、`M_Heater.PulseHeat_Up.SetTargetTempWithPlan(Real Steady_Time, Int16 Temperature)`
- 观测（读）：`o`/`i` 前缀，如 `oActualForce`、`oCurTemp`、`iSystemOn`
- 气路每一路有三种状态观测（`oPositiveState / oNegtiveState / oAirState`）+ 压强 `PressureSwitch.oValue` + 流量 `FlowMeter.oValue`

## 3. 层间接口定义

### 3.1 L1(GUI) ↔ L2(主控)　**待上位机资料（Q1）**

仿真侧先按 §6 的过渡 RPC 暴露下列**能力面**（从点位表 Command 反推 GUI 一定会用到的功能）：

- 流程类：开始/暂停/继续/停止/复位 工艺流程
- 运动类：单轴 move/jog/stop、回零、整机坐标系移动
- IO 类：任意 Observer 订阅、任意 Command 下发（气路三态、真空、灯塔、门锁）
- 温控类：开始/停止加热、预热、设温（脉冲加热 + 硅片台加热）
- 蓝膜台类（点位表 V10 口径，迭代 69 起）：`ES_Start / ES_Stop / ES_Reset / ES_EmergencyStop / ES_Initialize / ES_Photo(Allow) / ES_HeatAirGun(Open) / ES_ChangePunch(PunchNum) / ES_PickNozzle(PickNum) / ES_PlaceNozzle(PlaceNum) / ES_SetThetaAngle(Angle) / ES_ExpandingHeight`（外包模块，接口已固定在点位表；V6 的 ES_GvieBackDie/ES_MoveToNextChip 已删除）
- 搜力类（迭代 78 模型扩展点，V10 未定义）：`ForceSearch` / `StopForceSearch`，观测 `oActualForce` + `oForceSearchBusy/Done/Fail/Pos`。PLC 侧组合动作，从当前 BS_Arm_Z 下行，到力停轴并稳定确认；与完整 bond 流程的 `force_search` op 及 `BondingByForceManual` 力闭环分开。
- 加压类：`BondingByForceManual(Force, Speed)`，观测 `oActualForce`
- ACS buffer 类：`SetBufferNumber / RunBuffer / StopBuffer / ResumeBuffer`，观测 `oBufferDo / oBufferNum`

### 3.2 L2 ↔ L3(Motion/IO)　**待上位机资料（Q2）；仿真内部先自定义**

过渡期：仿真内部 L2→L3 用进程内调用或简单 TCP JSON（§6），语义与 3.1 能力面一致。

### 3.3 L3 ↔ ACS（SDK TCP）

真机为 ACS 厂商 SDK over TCP（具体指令集待确认 Q3）。模拟器实现一个 TCP 服务，支持：

- 轴指令：使能/回零（回零方式 17=负回零、18=正回零）/点位运动/停止/急停
- 状态观测：当前位置、运动中标志、到位标志、限位
- **伺服环动态**（2026-08-19 引入）：每轴一阶滞后模型产生跟随误差 PE（`pe`）与伺服实际位置（`x_actual`），轨迹跑完后须经到位整定（|pe| 在 settle_window 内持续 settle_time，默认约 50~70ms）才置到位标志；参数按轴分级（ACS 直轴 tau=0.005s / 旋转轴 0.008s / PLC 慢轴 0.015s，均为合成经验值，待真机标定），可经 9010 `/api/axis/config` 在线改 `tau/settle_window/settle_time`
- **buffer 机制**（点位表明确要求）：`SetBufferNumber(n)` / `RunBuffer` / `StopBuffer` / `ResumeBuffer`，观测 `oBufferDo / oBufferNum`——翻转交接等固化在 ACS 侧的动作序列以 buffer 程序形式预置在模拟器中（buffer 步进吃到位置到标志，自动继承整定延迟）

### 3.4 L3 ↔ PLC（HTTP）

- **扫描周期语义**（2026-08-19 引入，模拟倍福周期任务）：点位写入进输入映像，每 `plc_scan_ms`（默认 4ms，合成默认值，真机任务周期待确认）由物理线程 commit 进输出映像——写入最多晚一个扫描周期被 `/io/observe` 读到，观测以扫描率采样；扫描周期可在线改（9010 `POST /api/plc/scan {"ms":1~50}`，`/health` 带出当前值，config_overrides.json 持久化）

## 6. 仿真过渡协议（自定义，待真机资料到位后加适配层）

原则：语义层（变量路径、Command/Observer、能力面）不变，只换传输层报文。**单位约定：直线 mm、旋转 rad（全线统一 rad）**；TwinDOM 前端模型内部旋转轴为 deg，由前端注入脚本在边界换算。

- **ACS 模拟器**：TCP 服务，换行分隔 JSON：`{"cmd":"move","axis":"WS_LS_X","target":100.0,"speed":0.2}` / `{"cmd":"runBuffer","buffer":3}`；查询 `{"cmd":"get","what":"positions"}`。轴内部 50~200Hz 积分（S 曲线规划，算法借 backend 项目 `trajectory.py`）。
- **PLC 模拟器**：HTTP 服务：`POST /io/command {"path":"SystemMachine.SS_ME.M_AIR.WT_WaferVac","cmd":"OpenNegtive"}`；`GET /io/observe?path=...`；`GET /io/snapshot` 全量。内部维护 `GVL_IO.*` 状态表 + 简单物理（真空建立/破坏延迟、压强流量随阀门变化），状态表按扫描周期语义工作（写→输入映像→周期 commit→输出映像，默认 4ms，见 §3.4）。命令路由全覆盖（详见 plc_http.py 模块 docstring）：气路三阀、温控计划曲线、塔灯 UpdateMode（args 字典/位置数组双兼容）与 SetBool 手动点灯、电源分系统 On/Off（断电分系统的轴 move 报 409）、互锁 AllDoors_Reset/Mask 与单侧使能、相机触发（AlignCameraTigger_1/2、AS_CameraOn → 拍照记录，9010 `GET /api/camera/captures` 回读）、光源 SetBool 镜像 o* 观测位、WaferHeatReset、AramPosSensorCalibrate_1/2、ES_* 流程命令、BondingByForceManual、buffer 转发；备用/预留点位（Reserve/Spare/备用/预留）返回 ok:true 备注 spare 不报错；其余 SetBool/SetValue/Pulse 通用写入并镜像同级 o* 观测点。真空密封物理：有工件=密封（-80kPa/0.5 L/min）、无片=泄漏（-30kPa/10 L/min），grip_ok 供"有无片判断"（见《前后端数据协议_V1.md》§1）。

**别名机制（迭代 49，calibration.py:1469-1486）**：
bond_temp_calib/bond_force_calib 的 measured 同时带**显示别名键**
（gain/offset_c/offset_n——panel 测校页按 res.measured 键名渲染
勾选）与**常数名同值键**（head_temp_gain 等）。apply 对这两个
routine 先把 fields 里的别名改写路由到本作业的常数名键（同值，
写回目标不变）——否则别名键不在路由表会落 cameras 组 400。改写
规则：在 **job.result.measured 全量键**里找 ∈ 路由表且以 `_gain`
结尾者 → 别名 `gain` 指向它；`_offset_c`/`_offset_n` 同理映射
`offset_c`/`offset_n`（:1474-1486）。**别名表必须从全量
measured 建、不能用 fields 过滤后的子集**——用户只勾选别名键时
子集内没有常数名键，映射建空、别名原样漏进 cameras 组 400（迭代
49 修过的 bug；回归 test_metrology `i49.force_calib_apply_alias`）。
