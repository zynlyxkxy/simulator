## 0. 30 秒项目定位

我以 D2W 键合设备全链路仿真项目作为讨论的事实基础。一句话：**为一台真实存在的 die-to-wafer 键合设备，建了一个可以跑完整工艺的数字模型**。

关键数字（都是实测口径，不是宣传口径）：

- **21 根轴**全伺服动态仿真，**422 个 IO 点** + 气路 / 温控 / 压控全信号体系；
- **三相机视觉**（下 / 上 / 粗，3000×3000 画幅，REAL 真实渲染 + FAST 解析双模式）+ 光谱共焦；
- **完整工艺链**：晶圆上片 → EGA 全局对准 → 翻转取片 → 芯片交接 → 调焦调平 → 逐键合位精对准 → 热压键合 → 键合后检测；
- **28 个测校项** + 一套按真机标准开发的 PyQt5 测校软件（18 项 GUI 程序）；
- **硬实时**：物理 tick 1000Hz、数据推送 500Hz、本机单向延迟 p50 < 1ms；
- 建设周期 **39 天**（前端 TwinDOM 4 天 / 后端模块集成 18 天 / 整机业务集成 4 天 / 业务流程调试 3 天 / 测校模块 10 天）；
- 质量防线：quick 回归 **417 条**（墙钟 ≤15 分钟）、全量 **457 条**，每日计划任务自动跑。

**免责口径（先讲清楚，后面所有讨论的前提）**：这个数字模型不追求外观与结构上的 1:1 复刻，重点保证**运动行为、信号语义与工艺逻辑**的正确性；仿真不替代真实，性能指标以真机实测为准。

## 1. 范式提炼：数字模型在设备系统设计中的六个角色

每一条都附本项目的事实锚点——这些不是设想，是已经发生的事。

### 1.1 接口契约先行：软件与整机解耦并行开发

**做法**：建模的第一步不是画结构，而是复刻真机的接口契约——下位机点位表（1928 运动固件点位表）、上位机 RPC 契约（Cordis MCS HTTP 五服务）、ACS SDK 指令面、以及测校用的 MQTT 线协议。仿真实现全部参照真机接口协议，上位机软件经 bridge 中转层与仿真对接。

**范式价值**：上位机、测校软件、工艺流程**与整机硬件并行开发**，不等真机排期。三方团队（整机软件、测校、算法）目前各自日常在仿真上工作。

**可迁移性证据**：PyQt5 测校软件按真机通讯标准开发，走 MQTT 线协议——**将来换 broker 地址即可上真机**，这是"在仿真上开发的软件能不能直接用"的硬检验。

### 1.2 行为正确，而非外观 1:1

**做法**：模型保真的是"机器怎么动、信号怎么来、工艺怎么走"，而不是钣金长什么样。三维外观用 TwinDOM 前端模型做可视化，后端的物理真值才是本体。

**范式价值**：建模成本降一个量级（39 天建完全链路），而软件开发、调试、测校验证所依赖的行为语义一个不缺。**讨论点**：哪些系统设计问题必须依赖结构级保真（如干涉、热变形分布），哪些不需要——我们用沙盒干涉检查（146 个碰撞盒）和工程近似热/模态模型回答了中间地带。

### 1.3 真值 / 认知双层 + 误差注入：让"异常"可以复现

**做法**：仿真内部维护两套数据——**物理真值**（机器实际是怎么样）与**控制器认知**（机器常数表以为机器是怎么样）。误差以可配置方式注入到真值侧：轴重复定位、非正交、上片偏移/旋转、热漂移（吸盘热胀、横梁弯曲）、模态振动、传感器增益/偏置、视觉噪声……测校和算法看到的只是"认知 + 测量链"，和真机处境完全一致。

**事实锚点**：传感校准测校项注入增益误差 0.3% 后，温度校准程序拟合出增益 1.0032，写回机器常数后发布读数精确回到真值——**"注入 → 测量 → 标定 → 补偿 → 闭环验证"全流程在仿真里跑通**，与真机标定方法论一致。

**范式价值**：真机上"碰运气才能遇到"的异常，在模型里是**可随时复现、可定量控制**的实验条件。这是"先验证后上机"的机理基础。

### 1.4 测校前移：测校体系与整机同步建成

**做法**：28 个测校项（重复性、非正交、旋转中心/增益、微旋、焦面、高度、温度/力校准、RxRy 旋转轴标定等）全部先在仿真上开发验证；测校软件按老平台架构开发，新架构完成后可在仿真上先行适配；每个测校项配 SOP 级技术文档（算法推导、API 契约、CSV 列定义、误差来源分析）。

**范式价值**：测校从"真机到场后的收尾工作"变成**分系统验收平台**——可验证四类内容：流程正确性、算法正确性、motion 与 IO 配合、数据记录格式。**明确不谈指标**：指标以真机实测为准。

### 1.5 调试支撑：把"资深工程师的排查环境"标准化

**做法**：整机坐标系方向对齐、相机内参/像元/微旋、非正交与补偿、承接/键合高度、EGA 锚定等**典型标定流程清单**可在仿真上完整走通；450+ 条自动回归保证任何改动不破坏既有行为。

**范式价值**：集成调试人员到岗即有一套"什么都能动、什么都能看、坏了能重来"的环境；排查思路沉淀为文档与回归用例，成为**共享、可积累、可持续更新的标准知识资产**。

### 1.6 工程近似模型可插拔：给专业模型留座

**做法**：模态仿真（21 轴 SISO + 9 全机 MIMO，fn 分布 18~110Hz 贴合整机一阶 20~100Hz 调研口径）与组件级热仿真（LPTN 21 节点能量守恒网络 + 辐射链）默认 OFF、可热切换，接口已开放。

**范式价值**：全链路模型先回答"系统级影响链通不通"（例如：键合头 300℃ → 辐射 → 对准相机 +2℃ → 光轴漂移 4.6µm），**精度让位给贯通**；更精细的专业模型（FEA/CFD 降阶模型）可以按同一接口接手。行业调研结论：这一形态与精密设备运行侧主流（E-ELT 误差预算工具、光刻机热 ROM）同代。

## 2. 对系统设计流程的改变：四个"前移"

| 传统流程 | 有数字模型之后 |
|---|---|
| 等真机排期才能联调 | **软件调试前移**：上位机/测校/工艺并行开发 |
| 真机到场才设计测校 | **测校前移**：测校流程/软件/SOP 先行，仿真上做分系统验收 |
| 异常靠现场碰 | **验证前移**：误差注入让异常可复现、可定量 |
| 指标验收在交付前 | **验收前移**：流程/算法/数据格式在仿真上先行验收，指标仍归真机 |

一句话：**从"等真机"到"先演练后上机"**。手册提供已知案例，模型提供机理支撑。

## 3. 诚实的边界声明（讨论前主动交底）

1. **仿真不替代真实**：性能指标（精度、UPH）以真机实测为准；仿真验证的是流程、算法、接口、数据格式的正确性。
2. **参数是工程估值**：热参数（CTE/换热系数/辐射发射率）、模态参数、传感噪声量级全是调研估值，**待真机标定**；已预留标定路线（阶跃辨识、热像/热电偶、FRF/OMA）。
3. **与真机的差异已知并文档化**：详见《仿真实现原理》§2"和真机一样吗？——不一样，而且要知道哪里不一样"、《仿真差距与路线图》。
4. **最大缺口**：模型可信度的闭环——参数辨识、真机数据同化、前馈补偿、标准化验证四个环节尚未建立（这也是行业调研确认的共性缺口）。
5. **本项目是"真机已存在"的逆向建模**：正向设计（真机还不存在）场景下范式如何成立，是我想在讨论中请教的问题。

## 4. 可复用资产清单（范式推广的落脚点）

- **后端仿真框架**：纯标准库 runtime（物理引擎 / 误差系统 / 视觉服务 / MQTT broker / 测校服务），后续项目可直接复用；
- **测校框架**：metrology 脚本包 + PyQt5 GUI 分层（ScriptWidget 基类 / MQTT 线协议适配），换设备换测校项即可；
- **接口契约文档体系**：接口规范、前后端数据协议、视觉系统、误差模型等 30+ 篇契约文档，"文件:行号"互锚的写法保证文档与代码同步；
- **回归基建**：417 条 quick / 457 条全量 + 每日计划任务 + 并行编排器——**数字模型的生命线是"持续可信"，没有回归的模型三个月就没人敢信了**；
- **AI 协同开发经验**：本项目全程 AI 辅助建设（39 天工期的直接原因），包括自然语言修模、文档收口、回归治理——这本身也是一种新范式。

## 5. 抛给会议的讨论问题

1. **推广的成本结构**：这套范式推广到下一型设备，哪些资产直接复用（框架/测校/回归），哪些必须重建（点位表/工艺/视觉场景）？重建工作量占比多少才划算？
2. **可信度闭环怎么建**：模型参数标定数据如何从真机回流？数据同化（真机测量实时修正模型状态）在工业设备上有没有先例可循？
3. **正向设计场景**：真机不存在时，模型的"真值"由谁定义？数字模型能否参与方案阶段的选型决策（如结构刚度 → 模态 → 对准精度预算）？
4. **误差模型的边界由谁定义**：工程近似模型（如我们的 LPTN 热网络、二阶模态叠加）的精度边界由谁验收？"够用"的判据是什么？
5. **多专业模型接入的接口标准**：热 / 模态 / 光学专业模型以什么形态接入全链路（FMI/FMU？自定义 API？），谁拥有"真值"？
6. **组织层面**：数字模型的维护责任归谁（设计 / 软件 / 工艺）？模型与真机的配置漂移如何防止？

## 6. 附：现场演示路线（如会上需要，5–8 分钟）

> 前提：本机 `start.bat` 启动后端（9010 端口），浏览器打开面板。每步注明"预期看到的画面"，避免现场翻车。

1. **面板总览**（1 min）：21 轴位置实时刷新、422 IO 状态、温控压控 PID 曲线——"这是一台没有硬件的设备在跑"。
2. **轴点动 + 3D 联机页**（1 min）：面板 jog 任意轴，3D 页面机构同步运动（500Hz 推送）。
3. **视觉页三相机 live**（1–2 min）：打开光源、下相机看晶圆标记、上相机看吸盘纹路——REAL 模式是逐像素渲染的 9MP 图像，不是贴图。
4. **测校工作台跑一项**（2–3 min）：跑"相机对准重复性（动态）"，看 Operation Log 逐拍出数、row/col 双趋势图、3σ 统计——**这是和真机测校软件同一套流程**。
5. **（可选）热仿真演示**（1–2 min）：打开热仿真开关，键合头升 300℃，看 21 节点温度传导、热变形 6DOF 实时值、辐射链热流——"系统级影响链是通的"。
6. **收尾**：热/模态开关还原 OFF（项目纪律：默认态逐位不变）。

演示时的口播重点：**"你们看到的每一帧画面、每一个读数，上位机软件看到的东西和连真机时一模一样——这就是范式的核心。"**
